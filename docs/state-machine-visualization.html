状态分类统计

按生命周期阶段

  • 调度前：PENDING, PREPARING, READY（3 个）
  • 调度中：QUEUED, ALLOCATED（2 个）
  • 执行中：RUNNING（1 个）
  • 执行后：VERIFYING, RESUME_VERIFY（2 个）
  • 中断：PAUSED, NEEDS_RETRY（2 个）
  • 终态：COMPLETED, FAILED, TIMEOUT, CANCELLED（4 个）

设计考量

  • PREPARING：260823 新增，解决 UI 操作后无反馈问题
  • VERIFYING：260819 修复 P7 审计缺陷（验证器注册但未调用）
  • NEEDS_RETRY：区分"可重试失败"与"永久失败"
  • 终态无出边：保证 DAG 不会"死而复生"

三层分裂问题（P-StatusSync）

问题表现

  • DB 状态 ≠ FSM 状态（映射丢失中间态）
  • 前端显示 ≠ DB 状态（ComputeEffectiveStatus 二次翻译）
  • 修复一层，另一层复发

根因分析

  • 14 态 → 7 个 DB 状态：多对一映射不可逆
  • 前端有独立的状态计算逻辑
  • 缺少单一事实源（Single Source of Truth）

优化方向

  • 状态精简 9 态（Phase 2）
  • 事件溯源（append-only 事件日志）
  • FSM 作为唯一状态源，DB/Front 只读投影

TransitionPolicy 策略链

Guard（前置条件）

在转移前执行，任一 Guard 返回 false 则拒绝转移。可设置 Fallback 降级到另一目标态。

示例：RUNNING→COMPLETED 前检查 Slot 是否释放

Action（后置操作）

在转移成功后执行，用于触发副作用（释放 Slot、通知下游、更新 DB）。

示例：进入 PAUSED 后取消 executor context

Fallback（降级路径）

当 Guard 失败时，不直接拒绝，而是转移到另一合法目标态。

示例：RUNNING→VERIFYING 失败 → 降级到 FAILED

StateInvariantChecker 不变量规则（260823 新增）

规则名 验证内容 严重度 设计意图
terminal_has_error FAILED/TIMEOUT 态必须携带 LastError Error 防止"静默失败"——失败节点必须有错误信息
verifying_has_path VERIFYING 态的 phase 必须有 verifier 注册 Warn 防止配置错误导致验证永远不通过
completed_via_verify COMPLETED 态需有 verified 标记或 skipVerify Warn 修复 P7 审计缺陷——验证器注册但未调用
retryable_consistent FAILED 态的 error 不能标记为 Retryable Error 防止可重试错误被误判为永久失败
