## 3. 具体检测风险场景

### 3.1 低风险场景 ✅

以下操作**极难被检测**：

```
✅ 单次页面访问 (GET /latp/69218.html)
✅ Sitemap访问 (GET /sitemap/images.xml)
✅ 偶尔的评论列表查询
✅ 静态资源访问 (CSS/JS/图片)
```

**原因**:
- 这些行为与正常用户浏览无异
- 无频率限制触发
- 不产生敏感操作

### 3.2 中风险场景 ⚠️

以下操作**可能被检测**：

```
⚠️ 高频API调用 (连续请求 /web-api/v1/galleries)
⚠️ 异常请求模式 (固定间隔、无Referer)
⚠️ 大量404请求 (探测不存在的端点)
⚠️ 无Cookie的敏感操作
```

**检测指标**:
- 请求频率异常 (> 10次/分钟)
- 请求头不完整 (缺少Accept-Language等)
- 行为模式机械化 (固定间隔)

### 3.3 高风险场景 ❌

以下操作**极易被检测**：

```
❌ 暴力破解端点 (大量404请求)
❌ 并发高频率请求 (> 100次/分钟)
❌ 明显的爬虫特征 (Scrapy默认UA等)
❌ 无视CSRF保护的表单提交
```

## 7. 实际爬虫建议

### 7.1 如果继续开发爬虫

```
✅ 必须做的:
1. 使用随机User-Agent池
2. 实现随机请求延迟 (0.5-3秒)
3. 维护Cookie会话
4. 携带正确的Referer
5. 实现错误退避机制
6. 限制单IP请求频率 (< 30次/分钟)

⚠️ 建议做的:
1. 使用代理池轮换IP
2. 模拟正常浏览路径
3. 添加请求头随机化
4. 实现人机行为模拟 (随机滚动等)

❌ 避免做的:
1. 固定请求间隔
2. 明显的爬虫UA
3. 高频并发请求
4. 大量404探测
5. 无视CSRF保护
```

### 7.2 风险最小化方案

**方案A: 保守策略 (推荐)**
- 请求频率: 10-20次/分钟
- 使用代理池: 5-10个IP轮换
- 延迟: 2-5秒随机
- 风险等级: 🟢 极低

**方案B: 平衡策略**
- 请求频率: 30-50次/分钟
- 使用代理池: 10-20个IP轮换
- 延迟: 0.5-2秒随机
- 风险等级: 🟡 中等

**方案C: 激进策略 (不推荐)**
- 请求频率: > 100次/分钟
- 无代理/单IP
- 无延迟
- 风险等级: 🔴 极高
